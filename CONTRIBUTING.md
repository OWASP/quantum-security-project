# Contributing to the OWASP Quantum Security Project

Thank you for helping improve this project. This repository is a community-driven, vendor-neutral documentation effort for quantum security risks, readiness guidance, and related research and project materials.

## Ways to contribute

You can contribute in several ways:

- Propose a new risk or revise an existing one.
- Improve wording, references, or examples in the Top 10 entries.
- Add supporting documentation, references, or project resources.
- Share your perspective and experiences in discussions.
- Report issues, questions, or gaps in the current draft.
- Propose the creation of spin-off tools or documents that support Top 10 entries.
- Suggest project process or documentation improvements.

## Before you start

Please review the project goals and tone before proposing changes:

- Keep the work vendor-neutral and practical.
- Focus on security risk, readiness, and mitigation guidance.
- Ground claims in published standards, regulations, or peer-reviewed research.
- Avoid unsupported marketing claims or product-specific promotion.
- Use AI responsibly (see further detail below).
- Respect the OWASP community ethos of openness, collaboration, and evidence.

## Suggested contribution workflow

1. Check whether a related issue or PR already exists.
2. For larger changes, or where there is likely to be debate, open an issue first to discuss the proposal.
3. For smaller changes that are unlikey to stir much discussion, create a PR against the current active sprint branch.
4. If you're not sure, jump onto our Slack channel and ask.

## Content expectations

### For Top 10 risk entries

New or revised entries should usually:

- Follow the structure in [quantum-top-10/_template.md](quantum-top-10/_template.md).
- Remain concise and actionable.
- Include meaningful references to accepted guidance, regulation, or research.
- Explain practical prevention and mitigation steps.
- Avoid speculative or hype-driven claims.

### For non-risk project materials

Please keep changes clear, organised, and consistent with the existing repository style. Markdown files should be easy to read and maintain.

## Review and acceptance

Contributions are reviewed by the community and project leads. We value:

- Human (not AI) insight & experience.
- Clear rationale.
- Evidence-based updates.
- Alignment with the project charter and mission.

Pull requests that are incomplete, speculative, or unsupported by evidence may be asked to be revised before acceptance.

## Responsible use of AI

AI tools may be used to support research, drafting, editing, and summarisation, but they must not replace human judgement, technical review, or evidence-based writing.

Contributors are expected to:

- Use AI as an assistive tool, not as an authority.
- Verify statements against reliable sources before publication.
- Review any AI-assisted draft for factual correctness, attribution, and tone.
- Avoid submitting content that is invented, misleading, or unsupported by evidence.
- Disclose substantial AI assistance.

For this project, the bar is high because the content is intended to support security practice and risk assessment. Contributors should treat AI-generated content as a draft that still requires expert scrutiny. Any references, standards, regulations, or technical claims must be verified independently.

When in doubt, prefer a smaller, evidence-based edit over a broad AI-generated rewrite. Human review remains mandatory for all substantive changes.

## Code of conduct

This project follows OWASP community norms and expects contributors to act respectfully, professionally, and constructively. Please be civil and evidence-based in all discussions.

## Reporting problems

If you find an issue, error, or missing reference, please open a GitHub issue with as much context as possible. 


## Work management

To manage work items, Issues and PRs will be tagged as follows:

**Issues**
`top10` - top10 entries
`comms` - publicity, social media, public relations, etc
`admin` - team structure, ways of working, processes, etc
`new-idea` - ideas for new sub-initiatives/sub-projects

**PRs**
`docs` - documentation, README.md updates, etc
`top10` - top10 entries
`awesomelist` - awesomelist updates
`tools` - tools & scripts to support the top10

This list of tags will be updated as the project evolves.
